# Crypto World’s Fair：规则核查与提交清单

核验日期：2026-10-05（北京时间）。本文件为内部中文研究，不是直接提交材料。

## 1. 参赛判断

推荐以 **OpenWorkProof Settlement** 暂名参赛：复用已有 OWP 协议，新增 Agent 服务交付、客户验收与链上托管结算应用。它必须能够实际运行，而不只是“证据摘要上链”或技术文档。

关键条件：披露 OWP 既有开发历史，明确赛期新增范围。FAQ 允许复用自己的旧代码，但只评价赛期内完成的工作；比赛面向尚未获得显著外部融资的新创业产品，不能仅把长期成熟产品换名提交。是否符合融资与主体资格仍需按实际情况核对，不能凭新增仓库就保证合格。[官方 FAQ](https://colosseum.com/hackathon)

本次推荐 **Solana Ecosystem**，不是虚构的“AI Agent 专项赛道”。Agent 服务是产品场景，Solana 是生态赛道。

## 5. 评审标准如何转化为工作

正式规则覆盖功能、潜在影响、创新、UX、开源组合与商业计划；FAQ 强调这是一场创业比赛，也会看团队对市场的理解、执行、沟通、可行性与已有需求。不能只交协议类名和测试数量。[正式规则](https://colosseum.com/legal/Crypto%20World%27s%20Fair%20Hackathon%20Rules.pdf)、[FAQ](https://colosseum.com/hackathon)

我们的对应证据：

- 功能：完整的托管入金、交付、验收和测试代币释放；附失败路径。
- 链的必要性：客户事先锁定预算，满足双方授权条件才释放；双方均能查验资金状态。
- 创新：把工作契约、授权、实际产物、验证和验收绑定到同一笔结算，而非只保存“Agent 已完成”的日志。
- UX：买方看到任务约定、验证差异、实际金额、拒绝理由与钱包交易含义，不必先理解协议对象。
- 开源：可复现例子、程序地址、版本及第三方许可，明确旧代码来源。
- 商业：先验证需要跨组织交付的 Coding Agent 服务商及其客户；收费与采用都先列为假设。
